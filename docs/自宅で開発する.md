# 自宅（DirectCloud の無い環境）で開発・動作確認する

**DirectCloud は必要ありません。** ビューアは「同期フォルダ」ではなく **ただのローカルフォルダ** を
File System Access API で開いているだけです。会社では DirectCloud の同期フォルダを、自宅では
普通のフォルダを選べば、まったく同じように動きます。

## 1. セットアップ

```
git clone <このリポジトリ>
cd Library-Viewer
npm install
npm run build          # → dist/library-viewer.html
```

`npm install` はビルドとテストのためだけに必要です。成果物の HTML 自体は npm も Node も使いません。

## 2. サンプルライブラリを作る

手元に STEP が無くても、実運用と同じ形のライブラリを生成できます。

```
npm run sample          # → sample-library/ を作る (再生成は npm run sample -- --clean)
```

```
sample-library/
  library-viewer.html                      ビルド済みビューア
  library.json / members.json              階層・ネーミングルール・名簿
  models/設計1課/P2026-001_検査装置A/ワークX/    変換済み (glb あり → すぐ表示)
  models/設計1課/P2026-007_検査装置A2/ワークX/   変換済み・寸法違い (横断比較用)
  models/設計2課/P2026-002_搬送装置B/ワークY/    未変換 (step のみ → 開くと glb を生成して書き戻す)
  inbox/                                   受信箱: ルール一致 2 件 + 不一致 1 件
  sample-step/                             ドラッグ&ドロップ用 (ルール一致 / 不一致)
```

3 つの装置は `BASE_PLATE` / `ARM_UNIT` / `COLUMN` / `HEAD_UNIT` というユニット名を共有しているので、
複数を読み込むと「案件横断」パネルの動きも確認できます。

## 3. 開いて確認する

`sample-library/library-viewer.html` を **ダブルクリック**（Chrome / Edge）→「ライブラリを開く」で
`sample-library` フォルダを選ぶだけです。

> `file://` は Chrome / Edge では secure context として扱われ、`showDirectoryPicker` も
> `DecompressionStream` も `localStorage` も `IndexedDB` も使えます（`test/env_check.mjs` で確認済み）。
> **開発用に HTTP サーバーを立てる必要はありません。** 本番と同じ `file://` で確認してください。

### ひと通り試す手順

| 確認したいこと | 操作 |
|---|---|
| 一覧（管理者レス） | 「ライブラリを開く」→ 3 件が部署ごとに並ぶ |
| 未変換 STEP の自動変換 | 「搬送装置B」の **開く** → 変換後 `.glb` がフォルダに増える |
| 案件横断 | 「検査装置A」を開き、「検査装置A2」を **追加** → 部品を選ぶと右パネルに同名ユニット、← → で順送り |
| ネーミングルール | `sample-step/P2026-009_...step` をドロップ →「格納する」が入力済みで開く |
| 受信箱 | 「取り込む」→ 2 件が階層に格納され、ルール不一致の 1 件だけ残る |
| ルール変更 | 「ルール」→ パターンを変えて「試す」に名前を入れると格納先が出る |
| テーマ | ヘッダーの ライト / ダーク（自動は 6:00〜18:00 がライト） |

## 4. 自動テスト

```
npm run test:step       # STEP 生成 → occt で階層が取れること
npm run test:glb        # GLB を gltf-transform で / ZIP を unzip で検証
npm test                # 上記 + ブラウザ通しテスト 3 本
npm run test:env        # file:// と http://localhost で使える API を確認
```

ブラウザテストは Playwright の Chromium を `file://` で開いて実行します。
`test/library_test.mjs` と `test/sample_library_test.mjs` は File System Access API を
**メモリ上の偽ハンドル**に差し替えて動かすので、フォルダ選択ダイアログは出ません（CI でも動きます）。

## 5. 会社に持っていくとき

`dist/library-viewer.html` を DirectCloud の共有フォルダのルートに置くだけです。
`sample-library/` は持っていきません（`models/` と `inbox/` は本番のフォルダに作られます）。

初回だけ、誰かが「格納する」か Fusion スクリプトを実行すると `library.json` が作られ、
保存階層とネーミングルールが固定されます。

## 会社でしか確認できないこと

以下は自宅では再現できないので、社内で確認してください。

- **Fusion スクリプト（`fusion/LibraryExport/`）の実機動作。** Fusion が無いと動かせません
- **DirectCloud の同期の振る舞い。** 大きい glb が同期される前に他の人が開いたときの見え方、
  同時に別々の人が同じ案件を格納したときの上書き
- **実物の STEP。** サンプルは 3 ソリッドの単純な形状です。数千ソリッドの装置での変換時間と操作感
