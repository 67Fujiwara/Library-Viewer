# 装置3Dビューア 開発プロンプト

以下をそのままコーディングエージェント（Claude Code など）に渡してください。

---

## 依頼内容

社内向けの「装置3Dビューア」を作ってください。STEPファイルを読み込んで3D表示し、構成ツリーから表示を切り替え、案件情報を付けてフォルダ階層に格納できる**単一のHTMLファイル**です。

## 前提条件（これが設計を決めています）

- **社内にサーバーが立てられません。** ビルドサーバーもWebサーバーも使えません
- 配布はクラウドストレージ（DirectCloud）の共有フォルダ経由。利用者はHTMLファイルをダブルクリックで開きます
- **CADデータは社外に出せません。** 一切の外部送信を禁止します。変換も表示もすべてブラウザ内で完結させてください
- インストール作業ゼロ、ネット接続不要で動くこと
- 利用環境は Windows の Chrome / Edge
- 複数人が同じファイルを使います

## 成果物

`device-tree-viewer.html` 1ファイル。ライブラリもWASMバイナリもすべてこの中に埋め込みます。目標サイズ5MB以下。

## 技術構成

### STEP読み込み
`occt-import-js`（OpenCASCADEのWebAssembly版、npm）を使います。

- `occt.ReadStepFile(Uint8Array, params)` を呼ぶと `{success, root, meshes}` が返ります
- `meshes[i]` は `{name, attributes:{position:{array}, normal:{array}}, index:{array}, color}`
- `root` は `{name, meshes:[メッシュ番号], children:[...]}` の**階層構造**。これがそのまま構成ツリーになります
- params: `{linearUnit:'millimeter', linearDeflectionType:'bounding_box_ratio', linearDeflection:数値, angularDeflection:数値}`

### WASMの埋め込み（重要）
`occt-import-js.wasm` は約7.6MB あります。そのままbase64にすると10MBを超えるので、**gzip圧縮してからbase64**にしてHTMLに埋め込んでください（約4.1MB）。

ブラウザ側では `DecompressionStream('gzip')` で展開し、emscriptenモジュールに `wasmBinary` として直接渡します。これで**wasmファイルのfetchが一切発生しません**。

```js
const stream = new Blob([b64ToBytes(WASM_GZ_B64)]).stream()
  .pipeThrough(new DecompressionStream('gzip'));
const buf = await new Response(stream).arrayBuffer();
const occt = await occtimportjs({ wasmBinary: new Uint8Array(buf) });
```

### 3D表示
three.js r128 の UMD ビルド（`build/three.min.js`）をHTMLに埋め込みます。

- **ESモジュールは使えません。** `file://` から開くとimportがCORSで失敗するためです。必ずUMDビルドを直接埋め込んでください
- `OrbitControls` は使わず、pointerイベントで自前実装してください（ESモジュール版しかないため）

### glb書き出し
three.js の `GLTFExporter` もESモジュールなので使えません。**GLBライターを自作してください。**

- JSONチャンク + BINチャンクの2チャンク構成
- 各bufferViewは4バイト境界にパディング
- POSITION accessor には `min`/`max` が必須
- indices は `UNSIGNED_INT`(5125)
- 1ソリッド = 1プリミティブ + 1マテリアル + 1ノード

### ビルド方法
npmで取得したファイルをテンプレートHTMLに文字列置換で差し込むだけのスクリプト（Python 20行程度）を用意してください。バンドラは使いません。

## 機能要件

### 1. 読み込み
- ウィンドウ全体へのドラッグ&ドロップ、およびファイル選択ボタン
- `.step` / `.stp`、複数同時可
- 複数ファイルを入れた場合、それぞれが独立した装置としてツリーに並ぶ
- 変換中はオーバーレイで進捗（何件目 / ファイル名）を表示。変換前に必ず2フレーム待ってオーバーレイを描画させること（メインスレッドが止まるため）

### 2. メッシュ精度
3段階のプリセットと「再変換」ボタン。元のSTEPバッファを保持しておき、精度変更時に再メッシュします。

| | linearDeflection | angularDeflection |
|---|---|---|
| 粗い（最軽量） | 0.006 | 1.0 |
| 標準 | 0.0012 | 0.5 |
| 細かい | 0.0003 | 0.25 |

### 3. 構成ツリー（アプリの中心）
STEPの階層をそのままツリーにします。各行の構成:

`[開閉] [チェックボックス] [部品名] [子の数] [ソロボタン]`

- **チェックボックスで表示/非表示。** これが主操作です
- **親は3状態**。子の一部だけ非表示なら `indeterminate` にすること
- **チェックしてもカメラを動かさないこと。** 表示切替のたびに視点が飛ぶと位置関係を見失います
- 行ホバーで、3D側の該当部品をハイライト
- ソロボタン（ホバーで出現）: その部品だけ表示 / もう一度押すと全部戻る
- 「すべて表示」「反転」「非表示を薄く残す」ボタン
- 「非表示を薄く残す」は、消した部品を opacity 0.07 のゴーストで残すモード
- 名前での絞り込み検索
- 「◯◯ / ◯◯ 表示中」のカウンタ

### 4. 3Dビュー
- 左ドラッグ回転 / 右ドラッグ・Shift+ドラッグで平行移動 / ホイールで拡大
- 部品を直接クリックして選択（レイキャスト）。ツリー側も連動してスクロール
- 選択部品はオレンジでハイライト
- 表示モード3種: **外観** / **半透明**（選択以外を透過）/ **断面**（クリッピング平面、X/Y/Z切替＋スライダ＋反転）
- エッジ表示トグル（`EdgesGeometry` は重いので、初回ONの時だけ生成する遅延処理にすること）
- 「全体表示」「この部品に寄る」
- モデルのスケールに合わせてグリッドとカメラのnear/farを自動調整

### 5. 案件横断の一覧
**複数案件のSTEPを同時に読み込んだとき、同じ名前のユニットを串刺しで見られるようにします。**

- 部品名で名寄せ。全角半角、空白、アンダースコア、ハイフン、末尾の連番やリビジョン表記を無視して突き合わせる
- 完全一致を「同一名」、前方一致を「類似」として区別
- 右パネルに、他の装置での同名ユニットを一覧表示。どの装置のものか、ツリー上のパス、ソリッド数、今見ているものとの三角形数の差（％）を出す
- ツリー行にも、他装置でも使われている部品には件数バッジを表示
- 一覧のカードを押すと、その装置の同じユニットへ移動。このとき**カメラの角度は変えず、注視点と距離だけ移す**こと（同じ向きのまま中身が入れ替わるので差分が見える）
- ← → キーでも順送り
- **同じタグ**の行も他の装置から並べる（名前が違うユニットを横断させる手段。右クリック →「タグを付ける」）
- **読み込んでいないライブラリの装置**も並べる（`index.json` の部品名を名寄せで当てる + その装置の行に付けたタグ）。
  カードを押すと追加読み込みして比較に入る。読み込んだ装置どうしだけの横断にしない

### 5b. 検索結果のフィルター
検索結果の見出しの下に、結果をさらに絞るフィルターを置きます。
- ピル型の facet（タグ ▾ / 名称 …）。押すと候補と件数が出て複数選べる（同じ facet は OR、facet どうしは AND）
- 選んでいるピルは塗りつぶし。「クリア」で全部外す。検索をやめると外れる
- 左のツリーにも同じ条件が効く（検索は 1 本の問い合わせ）
- **どの facet を出すかは設定（歯車 → 検索 → 検索結果のフィルター）で選ぶ。** 既定はタグと名称。
  種類 / 装置 / 部署 / 担当者 / 案件コード / 取引先 を足せる

### 6. 格納（ディレクトリへの保存）
「格納する」ボタンでダイアログを開きます。

**入力項目**
- 案件コード（必須）
- 装置名（必須。初期値はツリーのルート名）
- 対象ワーク
- 部署 / 担当者（必須）

**部署と担当者はツリー形式**にしてください。部署の行をクリックすると下に担当者が展開され、そこから選びます。名簿は `部署, 担当者` を1行ずつ書くテキストで編集でき、localStorageに保存します（file://で失敗する可能性があるので try/catch すること）。`members.json` としての書き出しも付けてください。

**保存先の階層**はプルダウンで選べるようにします。既定は1番目。

1. `models / 部署 / 案件コード_装置名 / 対象ワーク`
2. `models / 案件コード_装置名 / 対象ワーク`
3. `models / 対象ワーク / 案件コード_装置名`
4. `models / 部署 / 案件コード_装置名`

入力に応じて実際のパスをリアルタイムでプレビュー表示してください。各セグメントは `\ / : * ? " < > |` を `_` に置換します。

**書き込み方は2通り**
- **File System Access API**（`showDirectoryPicker({mode:'readwrite'})`）で保存先フォルダを指定させ、`getDirectoryHandle(name, {create:true})` を順に辿ってフォルダを作り、直接書き込む。これが本命
- APIが使えない、またはフォルダ未指定の場合は**ZIPで書き出す**。ZIPの中に同じフォルダ階層を作ります。ライブラリは使わず、**格納方式（method 0、無圧縮）のZIPライターを自作**してください。CRC32テーブルと、ローカルヘッダ・セントラルディレクトリ・EOCDを組み立てるだけです。ファイル名は日本語を含むので**汎用フラグのbit 11（0x0800）を立ててUTF-8**にすること

**保存されるファイル**
```
<パス>/
  <元ファイル名>.glb        変換後のモデル
  step/<元ファイル名>.step  元ファイルのコピー
  meta.json                 案件コード、装置名、対象ワーク、部署、担当者、
                            保存日時、精度設定、各ファイルのサイズと三角形数
  index.json                構成ツリー（名称、階層パス、深さ、ソリッド数）
```

## デザイン

### DESIGN.md を視覚面の基準にする

プロジェクトルートで次を実行してください。

```
npx getdesign@latest add claude
```

生成される `DESIGN.md` が、**色・タイポグラフィ・余白・角丸・影・コンポーネントの作法についての唯一の基準**です。UIを書く前に必ず読み、そこで定義されたトークンとスケールに合わせてください。温かみのあるテラコッタ系のアクセントと、余白を効かせたエディトリアルなレイアウトが基調になります。

（このCLIはnpmからパッケージを取得して実行します。社内ネットワークで `npx` が通らない場合は、getdesign.md のサイトから `DESIGN.md` を手で取得してプロジェクトルートに置いてください。）

**DESIGN.md が扱っていない領域**は以下の方針で補ってください。

- **3Dビューポート**（背景・グリッド・エッジ線）はDESIGN.mdの範囲外です。ライト/ダークそれぞれで、地の色より2〜3段暗いニュートラルを選び、モデルの陰影が潰れないようにしてください
- 型式・寸法・三角形数などの数値は等幅フォント。DESIGN.mdに等幅の指定がなければシステム等幅で構いません
- アイコンはインラインSVGの線画。絵文字は使わないこと
- レイアウト構成は変更しません: ヘッダー / 左ツリー(310px) / 中央3Dビュー / 右横断パネル(288px) / フッター（選択部品の情報バー）
- クリック可能な要素は `<button>` `<a>` `<input>`+`<label>` を使い、divにクリックハンドラを付けないこと

### ライト / ダークの時刻自動切替

**昼はライト、夜はダークに自動で切り替わる**ようにしてください。

- 既定は「自動」。**6:00〜18:00 はライト、それ以外はダーク**
- ヘッダーに `自動 / ライト / ダーク` の3択を置き、手動で選んだ場合はそれを優先して localStorage に保存する（`file://` で失敗しうるので try/catch）
- 自動のときは**1分ごとに時刻を確認**し、境界をまたいだら切り替える。開きっぱなしで夕方を迎えても追従すること
- `<html>` の `data-theme="light" | "dark"` を切り替える方式。CSSカスタムプロパティは `:root`（ライト）と `[data-theme="dark"]` の両方に定義する
- 切替時は背景色と文字色に 0.2秒程度のトランジションを入れる。ただし**初回描画では走らせない**こと（読み込み時に色が流れて見えるため）
- DESIGN.md にダークの定義があればそれに従う。なければ色相を保ったまま明度を反転させて作り、アクセント色は暗い地の上で沈まないよう少し明るめに調整する

**3D側の連動を忘れないこと。** ここが一番抜けやすい箇所です。テーマ切替時に以下をすべて更新してください。

- レンダラのクリアカラー
- グリッドヘルパーの2色
- エッジ線の色
- 色情報を持たないソリッドの既定色
- 選択ハイライト色、ホバーハイライト色
- ビューポート上に重ねているHUDやツールバーの文字色

CSSカスタムプロパティを `getComputedStyle(document.documentElement).getPropertyValue(...)` で読んで three.js 側に渡す作りにすると、色の定義がCSSの一箇所で済みます。値をJS内に二重に持たないでください。

## 性能上の注意

- 部品を選択するたびにglbを生成しないこと。**保存ボタンを押したときに初めて生成**し、画面表示用のサイズは頂点数から概算する
- `EdgesGeometry` は部品数が多いと重いので遅延生成
- ホバーハイライトは毎回全メッシュを走査するとフレーム落ちするため、変化した分だけ更新する方が望ましい
- 大きいファイルの変換中はメインスレッドが止まります。将来的にはWeb Workerへ逃がす想定ですが、初版は同期で構いません

## 開発中の検証方法

テスト用のSTEPファイルが手元にない場合、**AP214形式のSTEPを生成するPythonスクリプトを書いて検証してください。**

1. 直方体を1つ持つ単純なSTEP（`MANIFOLD_SOLID_BREP` + `ADVANCED_BREP_SHAPE_REPRESENTATION` + 製品定義一式）
2. 3部品のアセンブリSTEP（`NEXT_ASSEMBLY_USAGE_OCCURRENCE` / `ITEM_DEFINED_TRANSFORMATION` / `CONTEXT_DEPENDENT_SHAPE_REPRESENTATION` で階層を作る）

2番目で `root` に階層と部品名が入ってくることを確認してください。ツリー機能の前提がここにあります。

書き出したglbの検証には `@gltf-transform/core` の `NodeIO` が使えます。メッシュ名、頂点数、バウンディングボックスが期待どおりか確認してください。

ZIPは実際に `unzip` で展開し、日本語のフォルダ名が壊れていないこと、中のglbが読めることを確認してください。

## つまずきやすい点

- `file://` から開くとESモジュールもfetchも使えません。**すべてクラシックスクリプトで、外部ファイル参照ゼロ**にしてください
- 埋め込むJSに `</script>` という文字列が含まれるとHTMLが壊れます。埋め込み前に必ず確認してください
- emscriptenに `wasmBinary` を渡せば `locateFile` は呼ばれません
- `DecompressionStream` は Chrome / Edge で使えます。未対応ブラウザではその旨を表示して終了してください
- ZIPの日本語ファイル名はフラグbit 11を立てないと文字化けします
- テーマの判定基準は **OSの設定ではなく時刻**です。`prefers-color-scheme` を分岐の条件に使わないでください（色の定義自体はCSS変数で持つこと）
- テーマを切り替えても3Dシーンの色は自動では変わりません。明示的に更新処理を呼んでください

## 進め方

1. `npx getdesign@latest add claude` を実行し、`DESIGN.md` を読んでトークンをCSSカスタムプロパティに落とす
2. ビルドスクリプトとテスト用STEP生成スクリプトを作り、`ReadStepFile` が動くことを確認する
3. GLBライターを書き、`@gltf-transform/core` で検証する
4. 読み込み・表示・精度切替までの最小版を作る
5. 構成ツリーとチェック操作を載せる
6. ライト/ダークの時刻自動切替を載せる（3D側の連動まで含めて）
7. 横断一覧を載せる
8. 格納ダイアログとZIP/File System Access APIを載せる

各段階で動くものを残しながら進めてください。
