# ライブラリ運用設計（管理者レス）

## ねらい

- 設計者は **格納するだけ**。登録・承認・一覧の保守といった管理者作業を作らない
- 見る人は **ダブルクリックで開くだけ**。インストールなし・サーバーなし・ネット不要
- CAD は Fusion。Fusion からの書き出しとビューアの格納が **同じフォルダ構造・同じ meta.json** を作る

## ライブラリ = 共有フォルダそのもの

DirectCloud で同期される共有フォルダを 1 つ「ライブラリ」と決めます。中央のデータベースはありません。
**フォルダと、各装置フォルダの `meta.json` が真実**です。ビューアは開くたびにフォルダを走査して一覧を作ります。

```
Library/                          ← DirectCloud の同期フォルダ
  library-viewer.html             ← ビューア本体 (dist/library-viewer.html をコピー)
  inbox/                          ← 受信箱: ルールに沿った名前の STEP をここに置くだけでよい
  library.json                    ← 保存階層の記録とネーミングルール (初回の格納時に自動生成)
  members.json                    ← 名簿 (部署, 担当者)。誰でもビューアの「名簿」から編集できる
  catalog.json                    ← 一覧キャッシュ (ビューアが自動生成。消えても問題ない)
  models/
    設計1課/                      ← 部署
      山田/                       ← 担当者 (この人が担当した装置がここに集まる)
        P2026-001_検査装置A/
          ワークX/
            検査装置A.glb.gz    ← 表示用 (ビューアが生成。gzip 済み。共有フォルダに残るのはこれだけ)
            meta.json           ← 案件コード・装置名・対象ワーク・取引先・部署・担当者・日時・ファイル情報
            index.json          ← 構成ツリー (名称・階層パス・深さ・ソリッド数)
```

### 共有フォルダに置くのは gzip した glb だけ

**STEP は共有フォルダに残しません。** マスターは Fusion のクラウドにあるので、
元データが要るときは装置カードの「Fusion で開く」から戻ってください。

容量が桁違いに変わるためです（実測）。

| 置き方 | 1 装置あたり |
|---|---|
| STEP + 素の glb（旧） | 25,471 B |
| **gzip した glb だけ（現在）** | **1,105 B = 23 分の 1** |

glb は形式を変えてもほとんど縮みません（float32 の座標が並ぶだけ）。効くのは gzip です。
展開はブラウザの標準機能で一瞬なので、開く速さは変わりません。

- Fusion スクリプトが置いた STEP は、**誰かが初めてその装置を開いたとき**に glb へ変換され、
  そのタイミングで共有フォルダから消えます（受信箱から取り込んだものも同じ）
- STEP を残したいときは、設定（左下の歯車）の **「共有フォルダに STEP も残す」** を入れてください。
  容量は 23 倍になりますが、あとから精度を変えて変換し直せます

### 保存階層は 1 つに固定

```
models / 部署 / 担当者 / 案件コード_装置名 / 対象ワーク
```

**選べません。** ライブラリ全体が同じ形でないと、フォルダを辿って探せなくなるためです
（ビューアと Fusion スクリプトの両方がこの形で書きます）。

担当者を階層に入れてあるので、**フォルダを開くだけで「その人が担当した装置」がまとまって見えます。**
ビューアの検索欄に担当者の名前を打っても同じ結果が出ます（後述）。

セグメント内の `\ / : * ? " < > |` は `_` に置換されます。対象ワーク未入力は `_` になります。

> 同じ装置を別の人が格納すると別のフォルダになります（担当者が違うため）。
> 引き継いだ装置は、古いほうをライブラリの「削除」で片づけてください。

## ネーミングルール（ファイル名だけで階層が決まる）

STEP のファイル名をこの形にしておくと、**ファイル名から案件情報を読み取って格納先の階層を自動で決めます。**

```
案件コード_装置名_対象ワーク_部署_担当者.step
P2026-001_検査装置A_ワークX_設計1課_山田.step
   → models/設計1課/山田/P2026-001_検査装置A/ワークX/
```

- パターンと区切り文字はビューアの「ライブラリ」タブ →「ルール」から変更でき、`library.json` に保存されて全員で共有されます
- 使える項目: `{projectCode}` `{deviceName}` `{workpiece}` `{customer}` `{department}` `{owner}`（`{projectCode}` と `{deviceName}` は必須）。
  ダイアログの項目ボタンを押すと末尾に足す / もう一度押すと外す。「既定に戻す」で戻る
- 既定は `{projectCode}_{deviceName}_{workpiece}_{department}_{owner}_{customer}`。**取引先は最後**に置いてある。
  末尾の「空でもよい項目」は無くてもよいので、取引先を足す前に付けた `…_設計1課_山田.step` もそのまま読める
  （ただし装置名に区切り文字が入っていて、かつ対象ワークも入っている古い名前は取り違えることがある。その場合は
  末尾に `_` を足して取引先を空にする）
  - **取引先 (`{customer}`) は既定のパターンに入っていません。** ファイル名から自動で入れたいときだけパターンに足してください。
    ルールに入れなくても、格納ダイアログで入力すれば `meta.json` に残り、検索にも当たります
- **区切り文字を含めてよいのは装置名だけ**です（`P1_組立_ライン_E_ワークX_設計2課_鈴木` → 装置名 `組立_ライン_E`）
- 対象ワーク・取引先が無いときは区切りを続けて書きます（`P1_装置A__設計1課_山田` → 対象ワーク空 → 階層は `_`）
- Fusion の書き出しに付く ` v3` や、全角の `＿` は自動で吸収します
- 名簿にない部署・担当者は、格納時に `members.json` へ自動追加されます

### 受信箱 (`inbox/`)

ルールに沿った名前の STEP を `inbox/` に放り込むだけで格納できます。フォルダを作る必要も、ビューアを操作する必要もありません。

1. 設計者は Fusion の書き出しなどで作った STEP を `inbox/` にコピーする（サブフォルダに入れても拾います）
2. 次に誰かがビューアで「ライブラリを開く」と、受信箱の中身とその格納先が一覧表示される
3. 「取り込む」を押すと、変換 → 階層を作って格納 → 受信箱から削除、までを一括で行う
4. 「ルール」ダイアログで「受信箱を自動で取り込む」を ON にすると、ライブラリを開いた時点で自動的に処理されます

ルールに合わない名前のファイルは取り込まず、受信箱に残したまま理由を表示します（消されません）。

## 3 つの格納ルート

### A. 受信箱に置くだけ（いちばん手軽）

ルールに沿った名前を付けて `inbox/` にコピーするだけ。詳細は上の「受信箱」を参照。

### B. Fusion から直接（推奨）

`fusion/LibraryExport/` を Fusion の「スクリプトとアドイン」に登録して実行します。

1. 初回だけ「フォルダを選ぶ…」でライブラリのフォルダ（同期フォルダ）を指定
2. 案件コード / 装置名 / 対象ワーク / 部署 / 担当者 を入力して「格納する」
3. **「メッシュで格納（推奨）」が既定**: Fusion が持っている三角形メッシュをそのまま `<名前>.glb.gz` に書きます。
   `meta.json` / `index.json` も一緒に書かれ、**ビューアはそれをそのまま開く**（変換なし。どんな大きさでも一瞬）
4. `meta.json` の `source` に Fusion のドキュメント名・バージョン・`fusionWebURL` が入る → ビューアの「Fusion で開く」リンクになる

「メッシュで格納」のときの選択肢:
- **メッシュの細かさ**（粗い / 標準 / 細かい）: Fusion 側で決めます。ビューアの精度設定はこのエントリには効きません
  （細かさを変えたければ Fusion から格納し直す）。節点は元の曲面上に乗っているので、計測の精度はどれでも同じです
- **STEP も一緒に書き出す**（既定オフ）: `step/` にも STEP を置きます。後でビューア側で再変換したいときだけ。容量は 23 倍
- 非表示にしてあるボディ・オカレンスは書き出しません（格納後のメッセージに件数が出ます）
- ツリーは Fusion のブラウザと同じ階層（オカレンス → ボディ）になります。組立位置はメッシュに焼き込まれるので `placement` は使いません

**「メッシュで格納」を外すと従来の STEP 格納**になります（`step/<名前>.step` を書き、ビューアが初回に開いたとき glb に変換して書き戻す）。
大きいアセンブリは「ユニットごとに分けて書き出す」で分割してください。
名簿にない部署・担当者を入力すると、その場で `members.json` に追加されます。

書き出す STEP のファイル名は**ネーミングルールに従って自動で命名**されます。そのため、この STEP を後からビューアに直接ドロップしても案件情報が復元されます。

### C. ビューアから

STEP をビューアにドロップ → 「格納する」。**ファイル名がルールに一致していれば、案件情報はすべて入力済みで開きます。**
ライブラリを開いていれば直接書き込み、開いていなければ ZIP を書き出します（ZIP はライブラリのルートで展開すると同じ階層になります）。

## 各ファイルのスキーマ

### meta.json

```json
{
  "schema": "library-viewer/1",
  "projectCode": "P2026-001", "deviceName": "検査装置A", "workpiece": "ワークX",
  "department": "設計1課", "owner": "山田", "savedAt": "2026-09-19T12:34:56+09:00",
  "precision": { "preset": "standard", "linearDeflection": 0.0012, "angularDeflection": 0.5 },
  "files": [
    { "name": "検査装置A", "glb": "検査装置A.glb", "step": "step/検査装置A.step",
      "stepSize": 123456, "glbSize": 45678, "triangles": 12345, "solids": 42, "rootName": "検査装置A" }
  ],
  "source": { "cad": "fusion", "document": "検査装置A v7", "version": 7, "dataFileId": "urn:...",
              "fusionWebURL": "https://....autodesk360.com/g/data/...", "exportedBy": "山田", "project": "案件P2026-001" }
}
```

ビューアは `schema` が `library-viewer` で始まるフォルダを装置として扱い、その下は走査しません。
`files[].glb` が無ければ「未変換」と表示し、開いたときに `step` から変換して glb を書きます。

### index.json

```json
{ "schema": "library-viewer/index/1",
  "devices": [ { "file": "検査装置A", "rootName": "検査装置A",
                 "tree": [ { "name": "検査装置A", "path": "検査装置A", "depth": 0, "solids": 42 },
                           { "name": "ARM_UNIT", "path": "検査装置A/ARM_UNIT", "depth": 1, "solids": 7 } ] } ] }
```

### members.json / library.json / catalog.json

- `members.json`: `{ "members": [ { "department": "設計1課", "name": "山田" } ] }`
- `library.json`: `{ "layout": "models / 部署 / 担当者 / 案件コード_装置名 / 対象ワーク", "naming": { "pattern": "{projectCode}_{deviceName}_{workpiece}_{department}_{owner}_{customer}", "separator": "_" }, "inboxAuto": false }`
- `catalog.json`: ビューアが走査結果を書き出すキャッシュ。次に開いたとき走査を待たずに一覧を出すのに使い、裏で走査して直す。Fusion スクリプトが案件コード候補にも使う

## 運用ルール（人が守るのはこれだけ）

1. 新しい装置は **`inbox/` に置く / Fusion スクリプト / ビューアの「格納する」のどれかで入れる**（手で models/ 配下にフォルダを作らない → `meta.json` が無いと一覧に出ない）
2. 更新は同じ案件コード・装置名・対象ワークで格納し直す（同じフォルダに上書き。`savedAt` が新しくなる）
3. 消したいときは、ライブラリ一覧のカードにある **「削除」** を押す
   - 何が消えるか（パスとファイル一覧・格納者）を確認してから実行します
   - 装置フォルダごと消え、その結果 **空になった案件フォルダ・部署フォルダも自動で片づけます**
   - **共有フォルダから消えるので、ライブラリを見ている全員から見えなくなります。** 元に戻す機能はありません
     （DirectCloud 側にゴミ箱や版数管理があれば、そちらから戻せる場合があります）
   - エクスプローラでフォルダごと削除しても同じです（次の走査で一覧から消えます）

## 想定 FAQ

- **同期が遅くて glb がまだ無い**: 「未変換」表示のまま開けば、その PC で変換して書き戻します
- **ライブラリを開くボタンで毎回フォルダを選ぶのが面倒**: 一度選べば場所を覚えるので、2 回目からは **html を開いた時点で自動で読み込みます**。
  ブラウザの権限ダイアログで「毎回このサイトで許可」を選んでおけばフォルダ選択も権限確認も出ません（Chrome / Edge 122 以降）。
  それ以外のときはライブラリタブが開いて「接続する」ボタンが出るので、1 回押すだけです（フォルダを選び直す必要はありません）。
  自動で読み込みたくないときは同じ場所の「開いたときに自動で読み込む」を外してください。別のフォルダにしたいときは「変更…」、覚えさせたくないときは「解除」です
- **大きい STEP に時間がかかる / 「変換できませんでした」になる**: ファイルサイズが原因です。
  実測（標準精度・変換のみ）は **1.4MB で 3 秒 / 19MB で 102 秒 / 59MB で 12.7 分 / 120MB で 51 分**。
  **時間はファイルサイズの 2 乗に比例します**（倍の大きさ = 4 倍の時間）。だから大きいファイルほど急に不利になり、
  逆に**分けると劇的に速くなります**（120MB を 20MB × 6 に分ければ 51 分 → 8 分）。
  数百 MB になるとメモリが足りず失敗します（STEP は読み込むとファイルの何倍にもふくらみ、
  ブラウザの 32bit WASM は 4GB が上限）。実際に 373MB のファイルが失敗しています。
  **目安は 20MB 以下が実用的、それ以上は分単位の待ち、数百 MB は失敗**です。
  装置まるごと 1 ファイルではなく、**ユニット単位（搬送部・検査部…）で書き出して**ビューアの「追加」で
  並べてください。構成ツリーでフォルダにまとめれば階層も再現できます。
  **Fusion から格納するなら「メッシュで格納」（既定）にしておけば、この問題はそもそも起きません。**
  Fusion 自身のメッシュを glb.gz に書くので、ビューア側の変換を通らず、373MB のアセンブリでも開くのは一瞬です。
  STEP で格納するときは、スクリプトの **「ユニットごとに分けて書き出す」** にチェックを入れてください。
  ルート直下のユニットごとに STEP が分かれ、**ライブラリ上は今までどおり 1 件**のまま、
  ビューアで開くと全ユニットが組立位置どおりに並びます（操作は何も増えません。チェックは記憶されます）。
  なお**待たされるのは最初の 1 回だけ**です（同じファイルは変換キャッシュから一瞬で開き、
  ライブラリに格納すれば glb が共有フォルダに残るので、他の人は変換せずに開けます）
- **2 回目から速くなる仕組み**: ライブラリを開き直したとき、**前回から変わっていない装置は読み直しません**
  （`meta.json` の更新日時とサイズで判断）。一度開いた装置も各自の PC に控えが残るので、
  2 回目は共有フォルダを読みに行かずに表示します。誰かが新しく格納したものだけが読み込まれます
- **担当者で探したい**: 検索欄（右サイドバーの上）に名前を打つだけです。**保存先パスの語**
  （部署・担当者・案件コード・装置名・対象ワーク）はすべて検索に当たるので、
  「藤原」と打てば藤原さんが格納した装置が、**まだ読み込んでいないものも含めて**並びます。
  結果を押すとライブラリから読み込みます
- **目当ての装置が名前で探せない**: フォルダーにタグを付けてください（ツリーでフォルダーを右クリック →「タグを付ける…」）。検索欄は名称とタグの両方に当たり、当たったものは右パネルに並びます。選ぶとそれだけが表示に残ります。
  タグは**各自の PC に保存**されるもので、共有フォルダには書き込みません（同じフォルダーをまた開けば戻ります）
- **間違えて格納したものを消したい**: ライブラリ一覧のカードの「削除」から消せます。
  ビューアに読み込んだだけのものを画面から外したいときは、構成ツリーの装置行にある × を押してください（ファイルは消えません）
- **受信箱に入れたのに一覧に出ない**: ファイル名がルールに合っていません。受信箱の一覧に理由が出ます（「ルール」で例を確認できます）
- **DirectCloud のドライブ文字が人によって違う**: 各自が自分の PC のフォルダを選ぶだけなので問題ありません。パスは保存しません
