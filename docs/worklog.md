## 2026-09-19 サイドバー開閉時に画面が暗くなる問題

- 症状: 左右パネルを開閉するとアニメ中に画面が暗くちらつく
- 原因: `Viewer3D.resize()` が `renderer.setSize()` のあと `requestRender()` で次の rAF に描画を回していた。
  `setSize` は描画バッファを作り直して空にするため、その差のフレームが黒として合成される。
  ResizeObserver は rAF のあと・ペイントの前に走るので、**リサイズしたフレームは必ず黒**になり、
  0.18 秒のアニメ中は毎フレームそれが起きていた
- 計測: アプリより後に登録した ResizeObserver から `gl.readPixels` して確認
  - 修正前 5/5 のリサイズで `[0,0,0]` / 修正後 0/5（背景色 `[227,221,211]` が読める）
- 修正: `resize()` 内で `renderNow()` を呼び、同じフレームで描き切る。
  サイズが変わっていないときは早期 return して無駄な再描画もしない
- `test/panels_test.mjs` に黒フレーム 0 を確認する回帰テストを追加

## 2026-09-19 穴の中心スナップと角度計測（精度の検証つき）

「STEP を直接読んだ方が精度が高いのでは」という問いに対し、**実測して不要と判断した**。

- 検証用に `tools/gen_test_step.py` へ穴あき板を追加（200x120x10、φ16 の穴が (50,60)/(150,60)、φ25 が (100,30)）。
  `CYLINDRICAL_SURFACE` + シーム辺 + 平面の内周ループで構成
- **OCC のメッシュ節点は元の曲面上に厳密に乗っている**ことを確認:
  公称円からのずれは 倍精度で 7e-15 mm、float32 に丸めても 3e-6 mm。粗い設定でも同じ（分割数が減るだけ）
- したがって円を当てはめれば中心・径は公称値と一致する。実測（穴中心間距離、公称 100mm）:
  粗い 100.000002522 / 標準 100.000000000 / 細かい 99.999998824 mm
- **STEP 直読みは採らない**。精度が理由ではなく、(1) アセンブリの座標変換チェーンを自前で再現する必要があり
  間違えやすい (2) ライブラリから glb を開いたときに STEP が手元に無く機能しなくなる、の 2 点
- `src/js/05b-circle.js`: 法線が連続する面をフラッドフィル → 境界ループを抽出 → Kåsa の線形最小二乗で円を当てはめ、
  残差 / 半径 < 1e-3 のものを円と認める。穴の内壁でも、穴のまわりの平面でも拾える
  （円周までの距離が最も近い円を選ぶ）。三角形ごとに結果をキャッシュ
- 角度計測（3 点）を追加。円弧と角度ラベルを描く
- **見つけたバグ**: 装置を読み込み直しても計測の点が残っていた（消えた形状を指したまま）。
  `removeDevice` と再メッシュで `Measure.clear()` を呼ぶよう修正
- 法線ベースの手法は採らなかった: 頂点法線は平均化されていて非半径成分が最大 2.9e-2 あり、位置ほど正確ではない
