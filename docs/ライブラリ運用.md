# ライブラリ運用設計（管理者レス）

## ねらい

- 設計者は **格納するだけ**。登録・承認・一覧の保守といった管理者作業を作らない
- 見る人は **ダブルクリックで開くだけ**。インストールなし・サーバーなし・ネット不要
- CAD は Fusion。Fusion からの書き出しとビューアの格納が **同じフォルダ構造・同じ meta.json** を作る

## ライブラリ = 共有フォルダそのもの

DirectCloud で同期される共有フォルダを 1 つ「ライブラリ」と決めます。中央のデータベースはありません。
**フォルダと、各装置フォルダの `meta.json` が真実**です。ビューアは開くたびにフォルダを走査して一覧を作ります。

```
Library/                          ← DirectCloud の同期フォルダ
  library-viewer.html             ← ビューア本体 (dist/library-viewer.html をコピー)
  inbox/                          ← 受信箱: ルールに沿った名前の STEP をここに置くだけでよい
  library.json                    ← 保存階層とネーミングルールの固定 (初回の格納時に自動生成)
  members.json                    ← 名簿 (部署, 担当者)。誰でもビューアの「名簿」から編集できる
  catalog.json                    ← 一覧キャッシュ (ビューアが自動生成。消えても問題ない)
  models/
    設計1課/
      P2026-001_検査装置A/
        ワークX/
          検査装置A.glb           ← 表示用 (ビューアが生成)
          step/検査装置A.step     ← 元データ (Fusion からの書き出し)
          meta.json               ← 案件コード・装置名・対象ワーク・部署・担当者・日時・精度・ファイル情報
          index.json              ← 構成ツリー (名称・階層パス・深さ・ソリッド数)
```

### 保存階層のプリセット

最初に格納した人が選んだ階層が `library.json` に固定され、以後は全員（ビューア / Fusion スクリプト）がそれに従います。

| # | 階層 |
|---|---|
| 0 (既定) | `models / 部署 / 案件コード_装置名 / 対象ワーク` |
| 1 | `models / 案件コード_装置名 / 対象ワーク` |
| 2 | `models / 対象ワーク / 案件コード_装置名` |
| 3 | `models / 部署 / 案件コード_装置名` |

セグメント内の `\ / : * ? " < > |` は `_` に置換されます。対象ワーク未入力は `_` になります。

## ネーミングルール（ファイル名だけで階層が決まる）

STEP のファイル名をこの形にしておくと、**ファイル名から案件情報を読み取って格納先の階層を自動で決めます。**

```
案件コード_装置名_対象ワーク_部署_担当者.step
P2026-001_検査装置A_ワークX_設計1課_山田.step
   → models/設計1課/P2026-001_検査装置A/ワークX/
```

- パターンと区切り文字はビューアの「ライブラリ」タブ →「ルール」から変更でき、`library.json` に保存されて全員で共有されます
- 使える項目: `{projectCode}` `{deviceName}` `{workpiece}` `{department}` `{owner}`（`{projectCode}` と `{deviceName}` は必須）
- **区切り文字を含めてよいのは装置名だけ**です（`P1_組立_ライン_E_ワークX_設計2課_鈴木` → 装置名 `組立_ライン_E`）
- 対象ワークが無いときは区切りを続けて書きます（`P1_装置A__設計1課_山田` → 対象ワーク空 → 階層は `_`）
- Fusion の書き出しに付く ` v3` や、全角の `＿` は自動で吸収します
- 名簿にない部署・担当者は、格納時に `members.json` へ自動追加されます

### 受信箱 (`inbox/`)

ルールに沿った名前の STEP を `inbox/` に放り込むだけで格納できます。フォルダを作る必要も、ビューアを操作する必要もありません。

1. 設計者は Fusion の書き出しなどで作った STEP を `inbox/` にコピーする（サブフォルダに入れても拾います）
2. 次に誰かがビューアで「ライブラリを開く」と、受信箱の中身とその格納先が一覧表示される
3. 「取り込む」を押すと、変換 → 階層を作って格納 → 受信箱から削除、までを一括で行う
4. 「ルール」ダイアログで「受信箱を自動で取り込む」を ON にすると、ライブラリを開いた時点で自動的に処理されます

ルールに合わない名前のファイルは取り込まず、受信箱に残したまま理由を表示します（消されません）。

## 3 つの格納ルート

### A. 受信箱に置くだけ（いちばん手軽）

ルールに沿った名前を付けて `inbox/` にコピーするだけ。詳細は上の「受信箱」を参照。

### B. Fusion から直接（推奨）

`fusion/LibraryExport/` を Fusion の「スクリプトとアドイン」に登録して実行します。

1. 初回だけ「フォルダを選ぶ…」でライブラリのフォルダ（同期フォルダ）を指定
2. 案件コード / 装置名 / 対象ワーク / 部署 / 担当者 を入力して「格納する」
3. `step/<ドキュメント名>.step` と `meta.json` / `index.json` が書かれる
4. `meta.json` の `source` に Fusion のドキュメント名・バージョン・`fusionWebURL` が入る → ビューアの「Fusion で開く」リンクになる

**glb（表示用）は書きません。** ビューアがそのエントリを最初に開いたときに変換し、フォルダに書き戻します（2 回目以降は速い）。
名簿にない部署・担当者を入力すると、その場で `members.json` に追加されます。

書き出す STEP のファイル名は**ネーミングルールに従って自動で命名**されます。そのため、この STEP を後からビューアに直接ドロップしても案件情報が復元されます。

### C. ビューアから

STEP をビューアにドロップ → 「格納する」。**ファイル名がルールに一致していれば、案件情報はすべて入力済みで開きます。**
ライブラリを開いていれば直接書き込み、開いていなければ ZIP を書き出します（ZIP はライブラリのルートで展開すると同じ階層になります）。

## 各ファイルのスキーマ

### meta.json

```json
{
  "schema": "library-viewer/1",
  "projectCode": "P2026-001", "deviceName": "検査装置A", "workpiece": "ワークX",
  "department": "設計1課", "owner": "山田", "savedAt": "2026-09-19T12:34:56+09:00",
  "precision": { "preset": "standard", "linearDeflection": 0.0012, "angularDeflection": 0.5 },
  "files": [
    { "name": "検査装置A", "glb": "検査装置A.glb", "step": "step/検査装置A.step",
      "stepSize": 123456, "glbSize": 45678, "triangles": 12345, "solids": 42, "rootName": "検査装置A" }
  ],
  "source": { "cad": "fusion", "document": "検査装置A v7", "version": 7, "dataFileId": "urn:...",
              "fusionWebURL": "https://....autodesk360.com/g/data/...", "exportedBy": "山田", "project": "案件P2026-001" }
}
```

ビューアは `schema` が `library-viewer` で始まるフォルダを装置として扱い、その下は走査しません。
`files[].glb` が無ければ「未変換」と表示し、開いたときに `step` から変換して glb を書きます。

### index.json

```json
{ "schema": "library-viewer/index/1",
  "devices": [ { "file": "検査装置A", "rootName": "検査装置A",
                 "tree": [ { "name": "検査装置A", "path": "検査装置A", "depth": 0, "solids": 42 },
                           { "name": "ARM_UNIT", "path": "検査装置A/ARM_UNIT", "depth": 1, "solids": 7 } ] } ] }
```

### members.json / library.json / catalog.json

- `members.json`: `{ "members": [ { "department": "設計1課", "name": "山田" } ] }`
- `library.json`: `{ "layout": 0, "naming": { "pattern": "{projectCode}_{deviceName}_{workpiece}_{department}_{owner}", "separator": "_" }, "inboxAuto": false }`
- `catalog.json`: ビューアが走査結果を書き出すキャッシュ。Fusion スクリプトが案件コード候補に使う

## 運用ルール（人が守るのはこれだけ）

1. 新しい装置は **`inbox/` に置く / Fusion スクリプト / ビューアの「格納する」のどれかで入れる**（手で models/ 配下にフォルダを作らない → `meta.json` が無いと一覧に出ない）
2. 更新は同じ案件コード・装置名・対象ワークで格納し直す（同じフォルダに上書き。`savedAt` が新しくなる）
3. 消したいときは、ライブラリ一覧のカードにある **「削除」** を押す
   - 何が消えるか（パスとファイル一覧・格納者）を確認してから実行します
   - 装置フォルダごと消え、その結果 **空になった案件フォルダ・部署フォルダも自動で片づけます**
   - **共有フォルダから消えるので、ライブラリを見ている全員から見えなくなります。** 元に戻す機能はありません
     （DirectCloud 側にゴミ箱や版数管理があれば、そちらから戻せる場合があります）
   - エクスプローラでフォルダごと削除しても同じです（次の走査で一覧から消えます）

## 想定 FAQ

- **同期が遅くて glb がまだ無い**: 「未変換」表示のまま開けば、その PC で変換して書き戻します
- **ライブラリを開くボタンで毎回フォルダを選ぶのが面倒**: 一度選べば場所を覚えるので、2 回目からは **html を開いた時点で自動で読み込みます**。
  ブラウザの権限ダイアログで「毎回このサイトで許可」を選んでおけばフォルダ選択も権限確認も出ません（Chrome / Edge 122 以降）。
  それ以外のときはライブラリタブが開いて「接続する」ボタンが出るので、1 回押すだけです（フォルダを選び直す必要はありません）。
  自動で読み込みたくないときは同じ場所の「開いたときに自動で読み込む」を外してください。別のフォルダにしたいときは「変更…」、覚えさせたくないときは「解除」です
- **間違えて格納したものを消したい**: ライブラリ一覧のカードの「削除」から消せます。
  ビューアに読み込んだだけのものを画面から外したいときは、構成ツリーの装置行にある × を押してください（ファイルは消えません）
- **受信箱に入れたのに一覧に出ない**: ファイル名がルールに合っていません。受信箱の一覧に理由が出ます（「ルール」で例を確認できます）
- **DirectCloud のドライブ文字が人によって違う**: 各自が自分の PC のフォルダを選ぶだけなので問題ありません。パスは保存しません
